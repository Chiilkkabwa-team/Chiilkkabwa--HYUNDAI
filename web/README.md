# 치일까봐 — 웹 프로토타입

Android(AAOS) 앱을 만들기 전에 **흐름·문구·화면을 브라우저에서 먼저 시험**하기 위한 웹판입니다.
모든 신호는 **모의**입니다. 실제 차량·에뮬레이터 신호는 쓰지 않고, 차량을 제어하지도 않습니다.

## 구성
| 파일 | 내용 |
|---|---|
| `core.js` | `app/src/main/.../core/*`(Kotlin)를 옮긴 로직: 안전 게이트, 미션 판정 7종, 세션 상태 기계, 요약, 배지·레벨, 가상 주차 물리 |
| `app.js` | 화면 8개(A-1~A-8) + 일시 정지·내 기록·설정·수료 카드, 모의 차량, 가상 차량 콘솔, ‘다음 조작’ 안내 |
| `art.js` | 독자 디자인 SVG: 마스코트 ‘콩콩이’, 아이콘, 배지 엠블럼, Driving view 자리 그림 |
| `styles.css` | 디자인 토큰(docs/04 §1과 같음), 반응형(PC: 디스플레이+콘솔 / 휴대폰: 콘솔이 아래에서 올라오는 시트) |
| `sim.js` | 평가·강습 모드 가상 주행 시뮬레이션(차량 모델, 다른 차, 끼어들기 시나리오, 가상 센서, 상황 감지·점수) |
| `test/core.test.mjs` | Kotlin 시나리오 16개 + 시뮬레이션 6개 = 22개 테스트 |

## 실행
```bash
cd web && python3 -m http.server 8080   # http://localhost:8080
node --test web/test/core.test.mjs       # 저장소 루트에서
```
빌드 단계 없음(정적 파일). Vercel에는 `web/` 폴더를 그대로 올립니다.

## 모드
| 모드 | 내용 |
|---|---|
| 연습 | 기존 MVP 흐름(공개 SDK 읽기 범위를 흉내 낸 모의 신호) |
| 평가 | 가상 도로 주행 + 가상 센서 → 주행 리포트(점수·항목별·상황별 조언) |
| 강습 | 강습자 패널: 정지 요청, 최고 속도 제한, 차선 보조·크루즈 조절(제조사 협업 가정 콘셉트) |

평가·강습은 `sim.js`(가상 시뮬레이션). 키보드 ↑ 가속 · ↓ 브레이크 · ←→ 핸들 · 스페이스 = 강습자 정지. 자세한 규칙·한계는 docs/11 §7.

## 자동 시연
머리말의 [자동 시연] 또는 주소 끝에 `?demo=1`. 콘솔·앱 버튼을 실제로 눌러 가며 안전 확인 → 워밍업 → 가상 주차 → 페달 → 약속 → 주행 중 잠금 → 복기 저장까지 약 1분에 보여 준다. 콘솔을 직접 만지면 멈춘다.

## 지킨 규칙(CLAUDE.md §5)
- 모르면 잠근다: 앱을 열면 1.4초 동안 신호를 ‘확인 중’으로 두고, 기어 P·주차 브레이크·주행 제한 없음이 모두 확인돼야 시작
- 시작 이후 새 관측만: 이미 매고 있던 벨트는 풀었다 다시 매야 완료
- 출처 라벨: 화면·배지에 ‘모의’ 표시
- 주행 중 화면은 정적: 애니메이션·소리·토스트·버튼 없음
- 개인정보: 서버 없음, 기록은 브라우저 localStorage에만

## 품질 점검 (2026-11-05)
- 접근성: axe-core 4.10(WCAG 2 A/AA) — 7개 화면 위반 0건
- 성능(메인 스레드 점유, 8초 측정): 연습 정차 약 2%, 연습 주행 중 1.6%, 평가 정차 3.3%, 평가 주행 11%(가상 도로 60fps)
- 키보드: 칩·강습 패널에서 선택해도 포커스가 유지됨(조그 다이얼 대비)
- 회귀: 단위 테스트 22개, 연습·평가·강습 자동 시연 끝까지 통과, 가상 주차 3개 화면 크기 완료

## Kotlin 원본과 다른 점
- 가상 주차 ‘칸 안’ 판정을 **차체 중심** 기준으로 했다(원본은 뒤축 중심 → 차가 칸 밖으로 튀어나와도 성공이 됨). 옆 차 충돌 판정, 기준선, 궤적 미리보기 추가
- 페달 감각은 **브레이크 페달 압력**으로 한다(PRD F5 대안)
- 방향지시등 순서가 틀리면 ‘거의 다 왔어요. 한 번 더!’ 안내(완료 판정은 원본과 같음)
- PREPARING에서 Ready로 돌아오면 일시 정지를 해제(원본 버그 → Kotlin도 같이 고침)
