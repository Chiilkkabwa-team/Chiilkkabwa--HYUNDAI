## TL;DR — 이 7가지만 지키면 된다

1. **기획서는 이미 강하다. 이제 승부는 '증거'다.** 1차 서류 1건을 2분 안에 읽는다(11/3 회의, 멘토링 경험담). 그 2분 안에 "진짜 돌아가는 차량 앱"이라는 걸 보여 줄 것: **① 클릭 한 번 웹 체험(1분 자동 시연) ② 60초 에뮬레이터 영상 ③ GitHub + release APK.** 가산점은 "단계별"이라 셋 다 내는 게 최대치다.
2. **가장 약한 축은 '기술 활용성'이다.** 지금은 Vehicle SDK(+AAOS)만 쓴다. 공식 SDK는 5종이다. **TTS·STT는 ON_DEVICE 모드면 앱 등록이 필요 없고, NaviHelper는 신청 없이 쓸 수 있다**(문서 확인). Safety(경고등)·Tire·SideMirror·DrivingMode(크루즈)·HVAC(김서림 제거) 읽기도 미션으로 바로 연결된다. → "Pleos SDK 4종 + Gleo 연동 설계"로 한 단계 올린다.
3. **가장 위험한 건 '운전 점수' 방향이다.** 주최측이 직접 예시로 든 게 "안전운전 점수 앱"이다 → 가장 많은 팀이 낼 아이디어다. 게다가 우리 원칙("판단은 사람이")과도 부딪히고, 주행 중 기록은 규정 확인 전이다. → 점수는 **"차가 이미 경고한 순간을 주차 후 돌아보기"(2단계)**로 바꿔서 쓰고, 숫자는 남과 비교하지 않고 **내 지난 기록과만 비교**한다.
4. **강습자 정지 버튼·속도 제한은 "보여 주되 약속하지 않는다."** 3단계(제조사 협업) 비전으로 두고, 2차 PT 마지막 30초에 웹 콘셉트 시연으로 보여 준다. 실제 앱에서는 구현하지 않는다(CLAUDE.md §5, 공개 SDK에 제어 없음).
5. **차량 특화성을 증명하는 장면 3개에 모든 산출물을 맞춘다.** ① 벨트를 매면 차가 확인하고 음성으로 칭찬 ② 실제 핸들을 돌리면 화면 속 내 차 바퀴가 따라 꺾임 ③ 기어 D가 되는 순간 화면이 조용히 잠김. 영상·PT·별지 첫 장·웹 체험 모두 이 3장면에서 시작한다.
6. **사업성은 숫자보다 논리로 설득한다.** 핵심 논리는 "부모님 차(그랜저)로 배우는 자녀 + 첫 차(아반떼)"다. 여기에 쏘카 교육용 차량과 방문 연수 학원(2026.1 허용)을 B2B 가설로 붙이고, **실제 설문 응답 수**를 넣는다. 지어낸 수치는 선정 취소 사유다.
7. **D-10 일정:** 11/6 Day1 신호 시험 → 11/9 APK → 11/11 영상 → 11/13 설문 반영·문장 확정 → 11/14 블라인드 점검·리허설 → **11/15 오전 제출**(마감 당일 밤 제출 금지).

## 3. 힘을 몰아줄 다섯 곳 (우선순위대로)

### ① "차가 대답하는 3장면" — 모든 산출물의 시작점
| 장면 | 쓰는 신호 | 1초 메시지 |
|---|---|---|
| 벨트 '딸깍' → "딸깍, 좋아요!" + 음성 | Seat 벨트 체결 + TTS | 폰은 '했다'고 믿고, 차는 '했는지' 안다 |
| 실제 핸들 → 화면 속 내 차 바퀴 | SteeringWheel 각도 + CarInfo 차체 크기 | 내 차, 내 손으로 하는 주차 |
| 기어 D → 화면이 조용히 잠김 | CarUxRestrictions + 기어 | 달릴 땐 아무것도 하지 않는 앱 |
- **영상:** Virtual Console의 Highway 1인칭 테마(기어 P에서 전환 가능)를 왼쪽에, 앱을 오른쪽에 두고 찍는다. 실제 차처럼 보인다.
- **웹 체험:** 첫 화면에 "1분 자동 시연" 버튼(구현돼 있음). 1차 심사위원이 링크 하나만 눌러도 3장면을 본다.
- **별지 첫 장:** 3장면 캡처 3컷 + 한 줄씩.

### ② 기술 활용성 끌어올리기 — "SDK 4종 + Gleo"
| SDK | 문서상 상태 | 쓸 곳 | 1차 기획서 표기 |
|---|---|---|---|
| Vehicle (조회) | 신청 없이 사용 | 기존 8개 도메인 + **Safety 경고등, Tire 공기압, SideMirror, DrivingMode 크루즈, HVAC 김서림 제거** | 핵심 |
| TextToSpeech | ON_DEVICE 모드는 **앱 등록 불필요**(SDK 가이드). 단 프로젝트 화면에는 '준비 중' 표기(확인 필요) | 정차 중 음성 칭찬·안내 | "Pleos TTS ON_DEVICE, 미지원 시 Android TTS" |
| SpeechToText | ON_DEVICE 모드는 **앱 등록 불필요**(같은 조건) | 주차 후 복기를 말로: "오늘 어땠어요?" → "후진이 무서웠어" | 정차 중만 |
| NaviHelper | **신청 없이 사용**, 목적지·경유지 설정 | **연습 코스 넘기기**: 멘토가 정차 중 고른 코스를 순정 내비로 넘기면, 주행 중 안내는 내비가 음성으로 한다 → 0터치와 양립 | 2단계 또는 MVP+ |
| FusedLocation | 모델별, 준비 중 | 쓰지 않음(개인정보 최소화 원칙 유지) | "쓰지 않는 이유"를 한 줄 적으면 오히려 플러스 |
| Gleo Interface | App Schema(액션 최대 3개, 응답 7초) | `START_PRACTICE`("글레오, 치일까봐로 연습 시작"), `GET_LAST_GOAL`, `SAVE_REVIEW` | 별지에 스키마 JSON 초안 첨부(확장 계획) |

> 주의: 위 상태는 **문서 확인만** 한 것이다. Day1에 에뮬레이터에서 실제로 호출되는지 확인하고, 되는 것만 "구현"으로 쓴다. 기획서 5번의 "Pleos TTS(문서상 준비 중) → 안드로이드 기본 TTS로 대체"는 **"ON_DEVICE 모드 우선, 미지원 시 대체"로 고칠 것.**

### ③ 1차 2분 설계 — 읽히는 순서를 설계한다
- **한 줄 소개가 길다**(지금 3줄). 후보:
  - A. "주차된 내 차가, 운전 연습을 '확인'해 줍니다 — 연습 전 5분, 주행 중 0터치, 연습 후 3분."
  - B. "가족에게 운전을 배우는 초보를 위해, 차가 직접 확인해 주는 Pleos 강습모드."
  - C. "확인은 차가, 판단은 사람이 — 초보·장롱면허를 위한 주차 중 운전 연습 앱."
  - 추천: **A를 한 줄로 쓰고, 지금 문장은 둘째 줄 설명으로.**
- **2번이 길다.** 각 단락 첫 문장을 굵게, 숫자는 가장 센 3개만 본문에 남긴다: **64% 장롱면허, 58만 원 연수비, 주차 사고 30.2%(후진 53.8%)**. 나머지는 별지나 근거 대장으로.
- **별지 0쪽 "한눈에 보기"를 새로 만든다:** 문제 1줄 → 3장면 → 쓰는 SDK 아이콘 → 3단계 로드맵 → 링크 3개(QR 포함).

### ④ 진짜 사용자 증거 (지금 0개 → 반드시 1개 이상)
- **설문(구글폼, 11/6~11/12):** 20대 지인, 학교 커뮤니티, 가족 단톡. 문항은 완성본 Q6 초안을 쓴다. **응답 수를 그대로** 적는다(예: "응답 47명 중 …"). 목표 N≥40.
- **가족 페어 테스트 5쌍(웹 체험판):** 학습자+멘토가 함께 연습 모드를 한 번 끝까지 해 본다. 기록할 것: 완주 여부, 준비 단계 걸린 시간, "가장 좋았던 장면", "쓸 것 같은 상황". **측정값 그대로** 6번에 한 줄, 별지에 표.
- 회의 발언 수치(63%, 주차 80~95%, 보험료 비교)는 지금처럼 계속 쓰지 않는다.

### ⑤ 그룹 정합 스토리 — "현대차가 이미 걷는 길의 빈칸"
- 운전결심(연수 연결) → 드라이빙 플러스(체험 교육) → **치일까봐(내 차에서의 일상 연습)** → 강습 차량 프로파일(OEM, 특허 US12275402 방향)

## 5. '평가 모드 · 강습 모드'를 어떻게 다룰까 (어제 요청에 대한 판단)

| 질문 | 판단 |
|---|---|
| 심사위원이 좋아할까? | 숫자·지표를 좋아한다는 팀 판단(11/5 회의)은 맞다. 다만 "운전 점수"는 **주최측 예시와 같아서** 창의성을 깎는다 |
| 우리 원칙과 맞나? | "앱은 운전 실력을 판정하지 않는다"(기획서 3번·5번 명시)와 **정면으로 충돌**한다. 한 문서 안에 둘 다 있으면 논리 공격을 받는다 |
| 규정상 되나? | 주행 중 화면 변화는 금지, 주행 중 기록(저빈도·기기 내)은 **운영진 확인 필요**. 전후방·차선 센서 값은 공개 SDK에 없고, AAOS 14 ADAS 상태 속성은 권한 등급·Pleos 노출이 **확인 필요** |
| 강습자 패널(주행 중 조수석 화면)은? | Pleos Connect 화면은 운전석과 공유된다. 주행 중 터치 패널은 규정과 충돌한다 → **조수석 전용 입력(물리 버튼·조수석 디스플레이)을 가정한 3단계 콘셉트**로만 |

**추천 정리 — 세 겹 구조로 바꿔 말한다**
1. **연습 모드 (지금, 1차·2차 시연의 본체):** 공개 SDK 읽기만.
2. **주행 돌아보기 (2단계):** 급제동·급출발(속도 변화)을 **주차 후에만** 보여 준다. ⚠️ 11/5 오후 정정: 차선이탈·전방충돌·후측방 경고 같은 **ADAS 상태 속성은 `READ_ADAS_STATES`(Signature|Privileged) 권한이라 서드파티 앱은 읽을 수 없다**(Android Car 레퍼런스 확인). 속도는 `CAR_SPEED`(Dangerous, 사용자 허용)로 가능성이 있다. 차량 경고 기반 복기는 3단계(제조사 협업)로 옮긴다. Pleos Safety 경고등(telltale)에 ADAS 표시등이 포함되는지는 Day1 확인.
   - 앱이 판정하지 않고 차의 판단을 옮겨 줄 뿐이라 "확인은 차가" 원칙과 맞는다.
   - 숫자는 '연습 지표'라고 부르고, **지난번의 나와만** 비교한다.
   - 무리한 끼어들기 = "후측방 경고 + 방향지시등 + 차로 변경"은 **제조사 협업(3단계)에서만** 가능한 정의다(ADAS 권한).
3. **강습 차량 프로파일 (3단계, 제조사 협업):** 정지 요청, 속도 상한, 주행보조 강도 프리셋.

**웹 체험판에서 바꿀 것:**
- '평가' 탭 이름을 **'주행 돌아보기(2단계 콘셉트)'**로 바꾼다.
- 점수 대신 **'차가 알려 준 순간 N번'**을 제목으로, 점수는 보조로 둔다.
- '강습' 탭에 **"3단계 · 제조사 협업 가정 · 조수석 전용 입력 가정"**을 표시한다.
- 기본 탭은 '연습'으로 둔다. 제출용 링크는 연습 탭 자동 시연으로 연다.

## 13. Pleos 공식 문서 재검토 반영 (11/5 저녁)

**에뮬레이터 설치 절차**를 공식 문서 원문(*Pleos Connect Emulator 설치 및 실행*)과 대조해 정정했다(docs/03 §4, README).
빠져 있던 것: ① 이전 버전이 있으면 **삭제 후** 진행 ② **Show Package Details**를 켜야 이미지가 보임 ③ 설치 후 **Android Studio 재시작** ④ Advanced 설정 뒤 **Device 탭으로 돌아가** API 34 → *Pleos Connect v2.1.0 APIs* 선택 ⑤ minSdk 28의 이유(**차량 사이버 보안 — 사이닝 키 로테이션·리니지**).
→ 기획서 5번에 "minSdk 28은 차량 사이버 보안 요건" 한 줄을 넣으면 규정을 읽었다는 신호가 된다.
