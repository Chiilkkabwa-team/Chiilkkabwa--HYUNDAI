## 7. A가 데이터 모델을 제안한다 = B/C가 기다려야 한다?

**아니다. 세 명은 즉시 병렬 시작 가능하다.** A는 데이터를 **생성**하므로 최소 사건 형태의 초안을 제안하지만, B/C는 기존 웹 Mock을 사용해 자기 기능과 테스트를 먼저 진행한다. 타인의 사전 컨펌을 의무화하지 않는다.

| 파트 | 데이터 계약 없이 지금 착수 가능한 일 | 연결할 때 약속할 정보 |
|---|---|---|
| A | E1·E2 오류, 공개 API/Capability·속도 단위 검토 | `eventId`, `kind`, `elapsedMs`, 근거 수치+단위, `source`, 신호 상태 |
| B | E4·E5 오류·말투·Android TTS 가능 여부 | 같은 `eventId`, `VoiceResult: SPOKEN/SKIPPED/BLOCKED`, 발화 성공 시각·사유 |
| C | E3 오류·타임라인 UI·프로필/저장 검증 | 같은 `eventId`, `sessionId`, `profileId`, 프레임 시각·출처 |

**실제 구현 전 최소 공통 계약(필드명은 예시·미확정):** `VehicleSample`(시각/속도 단위/기어·브레이크/상태/출처) → `DriveEvent`(이벤트ID/세션ID/유형/발생시각/측정근거/출처) → `VoiceResult`(이벤트ID/실발화 여부/스킵 사유) → `SessionRecord`(프로필ID/타임라인/이벤트/삭제 정책). 기존 `VehicleSnapshot`, `web/voice.js`, `web/replay.js`와 충돌하지 않게 최소 규격만 기록하고 변경하면 팀에 공유한다.

**공통 파일 충돌 주의:** `web/app.js`는 A(콘솔)/B(음성연결)/C(복기·온보딩)가 함께 사용하는 파일이고, `web/core.js`는 A(벨트)/C(게이트), `ChiilViewModel.kt`·`Signals.kt`는 Android 공유 계약이다. **함수 단위로 작게 수정하고 병합 당사자가 최신 dev 가져오기·충돌 해결·회귀 테스트를 책임진다.** 다른 사람의 검토 회신을 기다리는 절차는 없다.
