# 06. 시험 계획 — T01~T14 · 단위 테스트 · 로그 양식

> TL;DR — 순수 로직은 `CoreLogicTest`(17개, 통과)로, 화면·신호는 에뮬레이터 + Virtual Console로 T01~T14. 한 번이라도 주행 제한 중 **화면 입력**이 열리거나, 모의 값이 실차로 표시되거나, 음성이 빈도 상한을 넘기면 시연 보류.

## 2. Virtual Console 수동 시험 절차(vehicle 플레이버)
1. `adb forward tcp:8088 tcp:8088` → 127.0.0.1:8088
2. Safety: 주차브레이크 ON, Motion: 기어 P → 앱 ‘연습 시작’ 활성 확인
3. Safety: 안전벨트 해제→체결 → 미션 1 완료 확인
4. Motion: 브레이크 밟음→뗌 → 미션 2
5. (방향지시등 콘솔 항목이 없으면 기록하고 건너뛰기 경로 시험)
6. Motion: 기어 D, 속도 20 → 잠금 화면, 소리·애니메이션 없음
7. Motion: 속도 0, 기어 P, 주차브레이크 ON → 복기 화면, 거리·시간 표시(트립 신호 여부 기록)
8. 미션 도중 6번 수행 → 재주차 후 같은 미션이 처음부터 다시 시작되는지
9. **음성(T13)**: 6번 상태에서 Motion 속도를 급하게 올림·내림 → 음성 1회 확인 → 45초 안에 다시 급제동해도 **말하지 않는지** 확인 → 내비 안내 재생 중 급제동 → 음성이 나오지 않고 **큐에도 쌓이지 않는지** 확인
10. **리플레이(T14)**: 7번(재주차) 뒤 리플레이 목록이 9번에서 만든 순간들과 일치하는지, 말한 항목에 🔊가 붙는지 확인

무응답·실패를 생략하지 않는다. 결과는 `docs/test_logs/YYYY-MM-DD.md`에 쌓는다.

## 4. 성능 측정(제출 전 1회)
- Android Studio Profiler: 정차 화면 CPU ≤25%, 주행 잠금 중 <5%, 메모리 ≤400MB
- 터치 → 화면 반응 0.25초 이내(미션 성공 피드백 포함)
- **음성 재생 중에도 주행 중 CPU <5%**를 지키는지 함께 측정(TTS는 시스템 프로세스에서 합성되지만 우리 쪽 폴링 주기를 같이 본다)

## 5. 웹 프로토타입 자동 시험(`web/`)
`node --test web/test/` — 순수 로직(core 포팅·음성 게이트·리플레이)과 axe-core 접근성, Playwright 자동 시연 3종(연습·평가·강습)을 함께 돌린다.
주행 중 음성은 **브라우저 Web Speech API**로 실제 소리를 내지만, 빈도·양보 규칙은 앱과 같은 코드(`web/voice.js`)를 쓴다 → 규칙 위반은 단위 테스트에서 먼저 잡힌다.
