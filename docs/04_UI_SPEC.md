# 04. UI 스펙 — 화면 8개 · 문구 · 디자인 토큰

## 0-1. Pleos Connect 화면 구성 (공식 디자인 가이드 원문, 2026-11-06 확인)
> 출처: document.pleos.ai › 디자인 가이드 › Getting Started › Display Layout / Status bar / GNB, Foundations › Typography

**화면 구성 요소** — 앱은 Application window 안에만 그린다. 나머지는 **시스템 UI**이고 앱보다 상위 레이어라 일시적으로 앱을 가릴 수 있다.

| 영역 | 담는 것 | 우리 앱 |
|---|---|---|
| Status bar | SP0 Static(도어락·검색) · SP0 Dynamic(알림센터·통화·프라이버시) · **40dp safe bounds** · SP1 Dynamic(다운로드·업데이트·WPC·하이패스·사운드) · SP1 Static(프로필·블루투스·네트워크) · Time(12/24h) · PAB · More | 그리지 않음 |
| **Driving view** | **Telltale, 속도, 차량 상태** 등 주행·안전 정보 | 가리지 않음. 우리 미션은 이 정보를 **읽기만** 한다 |
| GNB | ①운전석 공조(차량설정·Climate·FR/RR Def·편집 슬롯) ②앱 조작(고정 앱 Navigation·편집 슬롯 3·App library·최근 앱 2) ③조수석 공조 | 편집 슬롯에 들어가는 앱 중 하나가 되는 것이 목표 |
| Application window | 앱 1개 또는 2개 | **Landscape·Portrait 모두** 대응(방향 고정 금지) |

**화면 유형**: Connect-S(17 / 14.6 / 12.9인치) · Connect-W(와이드, Extended는 세로 확장) · Connect-WF(워터폴, 작은 해상도).
→ 웹 프로토타입을 390 / 768 / 1440 / 1920 폭에서 가로 넘침 없이 확인했다(2026-11-06).

**폰트**: 시스템 UI 폰트는 **Asta Sans**(한국어·영어). 가이드는 "브랜드가 폰트를 지정할 수 있으나 **캐릭터가 강조된 폰트는 지양**", **최소 12sp**, 줄 높이 1.5배 이상(실제 18px 이상)을 요구한다.
→ **앱에서 커스텀 서체를 지정하지 않는다.** 그래야 차량에서 시스템 폰트(Asta Sans)를 그대로 쓴다. Asta Sans는 Playground 회원 약관에 묶인 Design Asset이라 공개 웹 프로토타입에는 넣지 않고, 중립 서체로 대체했다.

## 0-2. 테마 — 다크 기본 + 라이트 (2026-11-09)
> 근거 원문: 현대자동차그룹 공식 소개글 「새로운 이동 경험을 만드는 차세대 인포테인먼트 시스템, Pleos Connect」
> *"운전자는 속도, 연비, 경로 안내 등 정보를 위젯 형태로 조합할 수 있으며, **눈부심을 줄이는 다크 테마를 기본으로 라이트 테마로 변경도 가능**하다."*

Pleos가 실제로 두 테마를 지원하므로 우리도 **다크를 기본으로 두고 라이트를 함께** 제공한다(머리 오른쪽 '밝게/어둡게' 버튼, 선택은 기기에 저장).

**색은 한 곳에만 있다** — `web/styles.css`의 `:root`(다크) / `:root[data-theme="light"]`(라이트).
화면(CSS)도, 가상 주차·가상 도로(캔버스)도 모두 이 토큰을 읽는다(`web/theme.js`의 `c()` / `alpha()`).
→ **코드에 색 리터럴을 적지 않는다.** 적으면 테마 하나가 반드시 깨진다(2026-11-09에 CSS 180개·JS 89개를 전부 토큰으로 옮겼다).

| 쓰임 | 토큰 | 다크 | 라이트 |
|---|---|---|---|
| 페이지 / 앱 창 / 카드 | `--page` `--bg` `--surface` | #0A0E13 / #0F141B / #1B2430 | #E7ECF3 / #F2F5F9 / #FFFFFF |
| 본문 / 보조 / 흐린 글자 | `--text` `--sub` `--muted` | #E9EEF5 / #B8C4D2 / #93A1B3 | #0F141A / #46525F / #5E6A78 |
| 주 색 / 그 위의 글자 | `--primary` `--on-primary` | #2F80ED / #FFFFFF | #0B5FD0 / #FFFFFF |
| 파란 바탕 위 파란 글자 | `--primary-text` | #A9CBFA | #084BA8 |
| 노란 강조 / 그 위의 글자 | `--yellow` `--on-accent` | #FFD66B / #1B2430 | #F0B429 / #2B1D00 |
| 도로·차 (캔버스) | `--road-*` `--car-*` | 어두운 아스팔트 | 밝은 아스팔트 |

**조심할 것 두 가지** (둘 다 한 번씩 당했다)
1. '밝은 강조색 위의 어두운 글자'에 `--surface`를 쓰면 안 된다 → 라이트에서 흰 글자가 되어 대비가 깨진다. `--on-accent`를 쓴다.
2. 도로 표지(`--sign-bg` / `--sign-text`)는 **두 테마에서 같다.** 실제 표지가 그렇기 때문이다.

**검증**: axe-core WCAG 2 A/AA를 **다크·라이트 각각** 돌려 위반 0건을 확인한다. 라이트에서만 걸리는 대비 미달이 실제로 4종 있었다.

## 0-3. AI 티 걷어내기 — unslop 다듬기 (2026-11-10)
> 도구: [unslop](https://github.com/heydamir/unslop) 스킬(Damir Sokolovsky, CC BY 4.0). 프로젝트 `.claude/skills/unslop`에 설치. 다른 세션에서 `/unslop`으로 부를 수 있다.

판정: **가벼운 슬롭** — 화면은 이미 Pleos 구조로 잡혀 있어 방향은 그대로 두고 찾은 것만 고쳤다(다듬기 모드).

방향(5줄)
- 제품: 운전이 두려운 사람이 주차된 차에서 조작을 확인받는 연습 앱
- 성격: 차분한, 정확한, 조금 다정한
- 세계: 차 실내와 계기판, 주차장 바닥의 칠한 선
- 순간: 가상 주차 화면, 주행 리플레이 타임라인
- 서명: 차가 확인했을 때 뜨는 초록 '확인' 알약 — 이것만 색을 쓴다

| 찾은 것 | 고친 것 |
|---|---|
| 굵기 800 제목 14곳, 700 28곳 | 600으로. 단 `.btn`은 700 유지(흰 글자+파랑 3.86:1이 WCAG '굵은 큰 글자'로 통과하려면 700 필요) |
| 작은 라벨 자간 넓힘(다음 조작·콘솔 묶음 제목), 작은 글자 음수 자간 | 0으로 |
| 페이지 배경 색 번짐(radial-gradient) | 단색 `--page` |
| 진행 막대·차트 막대의 색 그라데이션 | 한 색(한 뜻) |
| 화면 문구 느낌표 21곳("칸 안에 들어왔어요!", "수고했어요!") | 느낌표 없이. 칭찬은 구체적인 내용으로 전한다 |
| 주석 속 이모지 | 글로 |

남긴 것(이유)
- 온보딩의 반복 움직임: 장식이 아니라 흐름을 설명하는 그림이라 유지. reduced-motion이면 멈춘다
- 다음 조작 강조의 깜빡임: 지금 눌러야 할 곳을 알려 주는 상태라 유지
- 글자 크기 46종, 4px 격자를 벗어난 간격(6·10·14·18·22px 다수): 바꾸면 레이아웃 전체가 흔들려 마감 전에는 손대지 않는다. 제출 뒤 정리 후보(B57)

## 0. Pleos Connect 디자인 가이드 준수 (2026-11-05 반영)
> 출처: document.pleos.ai › 디자인 가이드(foundations/components/experiences), 주행 안전을 고려한 설계

| 원칙 | 가이드가 요구하는 것 | 치일까봐가 지키는 방식 |
|---|---|---|
| **Easy & Safe** | 한 손 조작, 손·발 움직임을 유도하지 않음 | 한 화면 한 행동, 최소 터치 76dp, 텍스트 입력 없음(칩 선택만) |
| **Glanceability** | **1~2초 안에** 정보 파악 | 제목 1줄 + 상태 1줄 + 버튼 1개. 미션 화면은 '지금 할 행동' 한 문장을 가장 크게 |
| **반응 속도** | 입력 후 **0.25초 이내** 응답, 지연 시 로딩 표시 | 신호 수신 즉시 화면 갱신(웹 프로토타입 측정: 입력→반영 한 프레임) |
| **주행 중 제한** | 동영상·애니메이션 이미지·자동 스크롤 금지 | DO 미선언 + 주행 중 정적 화면(애니메이션·소리·토스트 중단) |
| **Consistency** | 플랫폼 컴포넌트·레이아웃 관습 따르기 | 시스템 Driving view 영역을 가리지 않음, 상태 표시줄·하단 바는 시스템 영역으로 두고 앱은 그 안에 들어감 |
| **CCP 조그 다이얼** | rotate / tilt / push 포커스 이동 대응 | 모든 조작 요소가 포커스 가능하고, **선택 후에도 포커스가 유지**되도록 구현(웹 프로토타입에서 검증) |
| **폼팩터** | Connect-S / Connect-W, Standard 14.6·17 / Wide / Waterfall | 세로 1창·가로 2창 모두 동작, `screenOrientation` 고정하지 않음 |
| **하드웨어 접근** | 하드웨어 직접 접근 금지, SDK 표준 API만 | 읽기 전용 SDK 호출만. 제어 권한 미선언 |



> TL;DR — 가로 화면 기준, 왼쪽은 시스템 Driving view(앱이 가리지 않음). 한 화면 한 행동, 큰 버튼(76dp+), 본문 22sp, 성공은 초록·즉시 칭찬, 출처 라벨 상시. 시안은 `docs/reference/치일까봐_별지A-C_화면시안_구조도_선행사례.pdf` 별지 A.

## 2-1. 주행 중 음성 문구 원칙 (F12)
화면 문구보다 더 엄격하다. 운전 중에 들리는 말이라서다.

| 규칙 | 안 되는 말 | 되는 말 |
|---|---|---|
| **사실만, 지시 금지** | “핸들을 더 꺾으세요” | “방금 출발이 조금 급했어요.” |
| **한 문장, 2.5초** | “지금 속도가 조금 빠른데 앞차와 거리도 가까워서…” | “앞차와 조금 가까워요.” |
| **점수·평가 금지** | “방금 감점됐어요” / “지금 72점” | (사실 + 짧은 제안만) |
| **놀라게 하지 않기** | “위험!” / 경고음 선행 | 평상시 말투, 같은 음량 |
| **호칭·존댓말 고정** | “야”, “너” | “~했어요 / ~볼까요” |
| **반복 금지** | 같은 지적 연속 | 같은 종류는 주행당 최대 2회 |

- 재생 순서: 포커스 요청 → 성공하면 발화 → `abandonAudioFocusRequest`. 실패하면 **그 발화는 버린다**
- 화면에는 아무 변화도 주지 않는다(토스트·배지·점수 표시 금지)

## 2-2. 온보딩 — 처음 온 사람에게 (2026-11-09, `web/onboarding.js`)
웹판은 '차량 화면 + 가상 콘솔'이라는 낯선 구조라, 설명이 없으면 좌우가 뭔지 모르고 닫는다.
그래서 **제품의 흐름을 그대로** 5장면으로 보여 준다. 한 장면은 한 가지만 말한다.

| # | 태그 | 말하는 것 | 움직임 |
|---|---|---|---|
| 1 | 무엇인가요 | 면허는 있는데 운전석이 낯선 사람에게. "확인은 차가, 판단은 사람이" | 차를 감싸는 확인 고리가 퍼진다 |
| 2 | 연습 전 5분 · 주차 중 | 조작하면 차가 확인해 준다 | 확인 항목 3개가 차례로 들어온다 |
| 3 | 주행 중 · 0터치 | 화면은 쉬고 목소리만 남는다 | 도로가 흐르고 말풍선이 한 번 떴다 사라진다 |
| 4 | 연습 후 3분 | 오늘 있었던 일을 같이 돌아본다 | 기록이 한 줄씩 쌓인다 |
| 5 | 체험판 쓰는 법 | 왼쪽 차량 화면 / 오른쪽 가상 콘솔, 모드 3개 | 콘솔 손잡이가 움직이고 화살표가 왼쪽을 가리킨다 |

규칙
- 움직임은 **transform·opacity만** 쓴다(합성만으로 끝나 CPU를 먹지 않는다 — 주행 중 <5% 기준과 같은 이유)
- `prefers-reduced-motion`이면 **마지막 상태를 바로** 보여 준다(움직임 없음, 내용 손실 없음)
- 점 5개로 아무 단계나 바로 갈 수 있고, **← →** 로도 넘긴다(차량 조그 다이얼의 기본 동작이 좌우 이동이라서)
- 단계를 바꾸면 제목으로 포커스를 옮긴다(읽는 자리를 잃지 않게)
- 머리 오른쪽 **‘사용법’** 버튼으로 언제든 다시 연다

## 3. 레이아웃 규칙
- 세로 1창(portrait): 위에서 아래로 제목 → 상태 → 행동 1개
- 가로 2창(landscape, 후속): 왼쪽 학습자 미션, 오른쪽 멘토 카드(조수석 쪽)
- 텍스트 입력 없음(칩 선택만)
- CCP 조그 다이얼 포커스 이동 대응(후속): 버튼 순서 = 읽는 순서
